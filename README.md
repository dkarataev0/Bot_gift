# 🎁 Монитор улучшенных подарков Telegram

Telegram-бот, который обнаруживает **новые улучшения** коллекционных подарков Telegram (Upgrade → Unique Gift) почти сразу после того, как они произошли, показывает публичные характеристики подарка и текущего владельца и помогает предложить обмен.

---

## 1. Результаты проверки источников (что реально возможно)

| Вопрос | Результат проверки |
|---|---|
| Есть ли у Telegram глобальный поток (push/WebSocket) событий «пользователь улучшил подарок»? | **Нет.** Ни Bot API, ни MTProto не присылают такие события посторонним: апдейты о подарках получают только их отправитель/получатель/владелец. Готового публичного WebSocket-потока с документацией не найдено; недокументированные API сторонних сервисов (в т.ч. see.tg) проект **не использует** — их формат и стабильность не подтверждены. |
| Можно ли тогда надёжно узнавать о **фактических** улучшениях? | **Да.** При улучшении Telegram присваивает подарку **следующий порядковый номер** в коллекции (`PlushPepe-2826`), а счётчик «выпущено» растёт. Проверено на живых данных: `t.me/nft/PlushPepe-2825` существует, `…-2826` — редирект 302, на странице «2 825/2 861 issued». Значит, появление номера `N+1` = новое улучшение. |
| Источник без аккаунта | Публичные страницы `https://t.me/nft/<slug>`: коллекция, номер, модель/фон/узор с редкостью в %, отображаемое имя владельца, «выпущено/всего». **Username владельца там нет.** Ограничение частоты: при ~0,3+ запроса/с полные страницы начинают приходить «пустыми» (заглушка 200 без данных); проверки «номера ещё нет» (302) выдерживают ~1,5–2,5 запроса/с. Бот это учитывает: заглушка ≠ «подарка нет». |
| Источник с аккаунтом (рекомендуется) | Официальный **MTProto** `payments.getUniqueStarGift(slug)` (библиотека mtcute, слой 223): все характеристики + **владелец с username** (если публичен), признак **крафта** (`crafted`), выставлен ли на **продажу**, TON-адрес. Метод доступен **только пользовательскому аккаунту** (не боту) — нужен вход в аккаунт по QR-коду. Используется только чтение публичных данных. |
| Список всех коллекций | `https://fragment.com/gifts` (123 коллекции на 11.11.2026, обновляется каждые 30 мин) + каталог MTProto `payments.getStarGifts` + встроенный проверенный список на случай недоступности. О новых коллекциях бот сообщает. |

### Как бот различает события

| Событие | Как определяется | Достоверность |
|---|---|---|
| 🎁 **Фактическое улучшение** | Появился новый порядковый номер, которого не было при предыдущей проверке. С MTProto дополнительно подтверждается, что это не крафт. | MTProto: ✅ высокая. Web: 🟡 средняя (крафт не различается). Время улучшения — **окно между двумя проверками**. |
| 🛠 **Крафт** | Новый номер с флагом `crafted` (только MTProto). Отдельный тип, не «улучшение». | высокая |
| ⚪ **Новый номер после перерыва** | Сервис был выключен дольше 15 мин — номер новый, но время улучшения неточно. Сохраняется в историю, **уведомление не отправляется**. | низкая (по времени) |
| — **Первое обнаружение старого подарка** | При первом запуске бот запоминает текущий максимум номера в каждой коллекции и **не присылает** тысячи старых подарков. | — |
| 🔄 **Смена владельца** | Для подарков в ⭐ избранном: периодическая перепроверка. По ID владельца (MTProto) — высокая; только по имени (web) — низкая (мог просто смениться ник). | см. слева |
| 💰 **Выставлен на продажу** | Для избранного, только MTProto (`resell_amount`). | высокая |

> Текущий владелец не обязательно тот, кто улучшил подарок (подарок могли сразу передать). Скрытые владельцы не раскрываются.

### Реальная скорость

Push-событий нет, поэтому это **адаптивный опрос**: коллекции, где недавно были улучшения, и выбранные вами коллекции проверяются каждые ~3 с, менее активные — каждые 20–90 с. Фактическая задержка = окно между проверками; бот считает её в `/stats` (медиана и 90-й перцентиль).

- **С MTProto** (до 4 запросов/с, адаптивно при FLOOD_WAIT): горячие коллекции — секунды, полный обход всех коллекций — ~30–60 с.
- **Только web** (без аккаунта): горячие коллекции — секунды–десятки секунд, полный обход — несколько минут (ограничение t.me на частоту запросов).

## 2. Что нужно сделать вам (≈20 минут)

Все секреты задаются **только в настройках Render** (Environment). Никому их не пересылайте и не коммитьте в репозиторий.

### Шаг 1. Создать бота
1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя и username.
2. Скопируйте токен — это `BOT_TOKEN`.

### Шаг 2. База данных Supabase (бесплатно)
1. [supabase.com](https://supabase.com) → New project (регион ближе к Франкфурту, например `eu-central-1`). Запомните пароль БД.
2. Кнопка **Connect** вверху проекта → вкладка **Connection string** → тип **Session pooler** (важно: не «Direct connection», он работает только по IPv6, которого нет на Render).
3. Скопируйте строку вида `postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres` и подставьте пароль — это `DATABASE_URL`.
   Таблицы создаются автоматически при первом запуске.

### Шаг 3. Ключи MTProto (рекомендуется — нужны для username владельцев и скорости)
1. Войдите на [my.telegram.org](https://my.telegram.org) → **API development tools** → создайте приложение (название любое).
2. `App api_id` → `TG_API_ID`, `App api_hash` → `TG_API_HASH`.
3. Рекомендуется использовать **отдельный (второй) аккаунт** Telegram для входа в шаге 6 — бот только читает публичные данные, но так надёжнее.

Без этого шага бот работает только через публичные страницы t.me (без username владельцев).

### Шаг 4. Развернуть на Render
1. [render.com](https://render.com) → войдите через GitHub.
2. **New → Blueprint** → выберите этот репозиторий → Render прочитает `render.yaml`.
3. Заполните переменные: `BOT_TOKEN`, `DATABASE_URL`, `TG_API_ID`, `TG_API_HASH`. `SESSION_SECRET` сгенерируется сам. `ALLOWED_USER_IDS` можно оставить пустым (см. шаг 5).
4. **Apply** → дождитесь статуса **Live** (2–4 мин).

Стоимость: тариф **Starter ~7 $/мес** (бесплатный тариф Render «засыпает» без трафика — круглосуточный мониторинг на нём невозможен). Supabase — бесплатно (история хранится 30 дней, избранное — всегда).

### Шаг 5. Запустить бота
Напишите своему боту `/start`. **Первый, кто напишет `/start`, становится владельцем**, остальным бот отвечает «приватный бот». Хотите явно — укажите свой ID в `ALLOWED_USER_IDS` (бот показывает ID незнакомцам; или узнайте у [@userinfobot](https://t.me/userinfobot)).

### Шаг 6. Подключить аккаунт для MTProto
1. В боте: `/login`. Бот пришлёт QR-код.
2. На телефоне, в Telegram того аккаунта, который хотите подключить: **Настройки → Устройства → Подключить устройство** → отсканируйте QR.
3. Если включён облачный пароль — бот попросит его и **сразу удалит** сообщение с паролем.
4. Сессия сохраняется в БД **в зашифрованном виде** (ключ `SESSION_SECRET` хранится только в Render). `/status` покажет «MTProto ✅».

Отключить: `/logout` и в Telegram «Настройки → Устройства» завершить сеанс.

## 3. Как пользоваться

Всё управление — кнопками; команды тоже работают:

| Команда | Что делает |
|---|---|
| `/start` | главное меню |
| `/settings` | вкл/выкл уведомлений, уведомления о новых коллекциях и изменениях избранного, шаблон сообщения |
| `/filters` | фильтры: все/выбранные коллекции, отключение коллекций, только с публичным username, модели, редкость (≤5/2/1/0.5 % по модели/фону/узору/любому), крафт |
| `/latest` | последние обнаруженные улучшения (`/latest plushpepe` — по коллекции) |
| `/favorites` | избранное (отслеживается смена владельца и продажа) |
| `/stats` | количество улучшений за 1 ч/24 ч, задержка обнаружения, активные коллекции |
| `/status` | состояние БД, источников (темп, ошибки, FLOOD_WAIT), мониторинга, рассылки |
| `/gift <ссылка>` | карточка любого подарка, например `/gift https://t.me/nft/PlushPepe-1` |
| `/models Pumpkin, Cyberpunk` | фильтр по моделям (`/models clear` — сброс) |
| `/template <текст>` | шаблон предложения обмена (`{gift}`, `{link}`, `{owner}`) |
| `/login`, `/logout` | подключить/отключить аккаунт MTProto |

**Кнопки в уведомлении:**
- 🎁 **Открыть подарок** — страница `t.me/nft/...`.
- 👤 **Профиль владельца** — только если у владельца есть публичный username.
- 💬 **Предложить обмен** — открывает чат с владельцем и **подставляет черновик** (ссылка `t.me/<username>?text=...`); отправляете вы сами. Если username нет — кнопка **копирует** готовый текст.
- ⭐ **В избранное** — добавить/убрать.

Бот **никогда не пишет** незнакомым пользователям сам.

Если улучшений очень много, после 6 отдельных сообщений бот присылает сводку списком — сузьте фильтры.

## 4. Ограничения (честно)

- **Нет push-потока от Telegram** → только опрос; «мгновенно» = секунды для активных коллекций, но не 0.
- **Без MTProto** username владельца неизвестен (Telegram не показывает его на публичной странице), крафт не отличается от улучшения, статус продажи неизвестен.
- Владелец может быть скрыт настройками приватности — тогда «Неизвестно».
- Если сервис был выключен, подарки за это время попадут в историю (`/latest`, отмечены ⚪), но уведомления о них не придут.
- Лимиты t.me и MTProto не документированы; бот подстраивает темп автоматически (видно в `/status`).

## 5. Устройство проекта

```
src/
  index.ts                — запуск, связывание модулей, health-check (/health), корректная остановка
  config.ts               — переменные окружения
  sources/                — 1. получение данных
    web.ts                  публичные страницы t.me/nft + парсер (заглушка ≠ «нет подарка»)
    mtproto.ts              MTProto (mtcute): getUniqueStarGift, каталог, вход по QR
    router.ts               выбор источника и запасной путь
    catalog.ts              список коллекций (fragment.com, MTProto, встроенный)
  types.ts                — 2. нормализованная модель подарка (общая для источников)
  monitor/
    detector.ts             3. обнаружение новых номеров, первичная загрузка, окно времени, дедупликация
    scheduler.ts            адаптивное расписание проверок
    discovery.ts            новые коллекции
    ownerTracker.ts         4. смена владельца / продажа избранного
  db/                     — 5. PostgreSQL: миграции, репозиторий
  notify/
    filters.ts              6. фильтры
    format.ts / notifier.ts 7. сообщения, кнопки, рассылка без дублей
  bot/bot.ts              — 8. команды и меню настроек
  logger.ts               — 9. структурированные логи (pino)
```

Защита от дублей: уникальный ключ события `new:<slug>` в БД + отметка «отправлено пользователю» `(event_id, chat_id)`. Состояние (максимальный номер в каждой коллекции) хранится в БД, поэтому после перезапуска мониторинг продолжается с того же места.

## 6. Для разработчика

```bash
npm install
cp .env.example .env   # заполните
npm run dev            # запуск с автоперезагрузкой
npm test               # тесты (интеграционные с Postgres: TEST_DATABASE_URL=postgres://... npm test)
npm run check-sources  # живая проверка источников (fragment, t.me, MTProto при наличии TG_SESSION)
npm run login          # альтернатива /login: QR в терминале, печатает строку для TG_SESSION
```

Node.js 22+. Секреты читаются только из окружения; `.env` в `.gitignore`.
